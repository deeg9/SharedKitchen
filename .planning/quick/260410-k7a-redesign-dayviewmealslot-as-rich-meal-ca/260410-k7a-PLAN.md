  <name>Task 1: Create meal_rsvps migration and RSVP store</name>
  <files>supabase/migrations/00024_create_meal_rsvps.sql, src/stores/rsvpStore.ts</files>
  <action>
1. Create Supabase migration `supabase/migrations/00024_create_meal_rsvps.sql`:
   - Table `meal_rsvps` with columns:
     - `id` uuid DEFAULT gen_random_uuid() PRIMARY KEY
     - `meal_plan_id` uuid NOT NULL REFERENCES meal_plans(id) ON DELETE CASCADE
     - `user_id` uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE
     - `status` text NOT NULL CHECK (status IN ('eating', 'skipped')) DEFAULT 'eating'
     - `created_at` timestamptz DEFAULT now()
   - UNIQUE constraint on (meal_plan_id, user_id)
   - Enable RLS with policy: users can SELECT/INSERT/UPDATE rows where meal_plan_id belongs to a meal_plan in their household (join meal_plans -> household_id, check household_members)
   - Index on meal_plan_id for fast lookups

2. Create `src/stores/rsvpStore.ts` using Zustand (same pattern as other stores):
   - State: `rsvps: Map<string, { user_id: string; status: 'eating' | 'skipped' }[]>` keyed by meal_plan_id
   - `fetchRsvps(mealPlanIds: string[])`: batch-fetch RSVPs for multiple meal plans, populate map
   - `toggleRsvp(mealPlanId: string, userId: string)`: upsert row toggling between 'eating' and 'skipped'. Use Supabase upsert with onConflict: 'meal_plan_id,user_id'. Optimistically update local state before the DB call.
   - `ensureDefaults(mealPlanId: string, memberUserIds: string[])`: for a meal plan, insert 'eating' rows for any members who don't have an RSVP yet (ON CONFLICT DO NOTHING). This implements the opt-out model from CONTEXT.md decisions.
   - Export `useRsvpStore` hook.
  </action>
