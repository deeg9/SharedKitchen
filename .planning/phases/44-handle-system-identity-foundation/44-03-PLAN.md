Note on data model: kitchen_profiles is household-level (not user-level). The handle
column is on the profiles table (user-level). For feed cards, kitchen_profiles does NOT
have a direct FK to profiles. The relationship is: kitchen_profiles -> household_id ->
household_members -> user_id -> profiles. For Phase 44, we query the household admin's
handle (first household_member) via a Supabase nested select. If this query is too
complex, fall back to displaying kitchen display_name only and show handle only on the
profile screen. Feed handle display can be enhanced in Phase 45/48 when feed_posts track
the posting user_id.

Note on recipe detail: The recipes table has `created_by: string | null` which is a user_id
FK to auth.users. To get the creator's handle, query profiles table with that user_id.

   const { data: members } = await supabase
