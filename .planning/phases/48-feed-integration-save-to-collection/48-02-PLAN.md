  <action>
Rewrite the `saveRecipeFromPost` method in socialStore.ts (currently at line 656) to use the `clone_recipe_to_household` SECURITY DEFINER RPC function instead of the current direct SELECT + INSERT approach that fails RLS for cross-household recipes.

Replace the entire saveRecipeFromPost implementation with:

```typescript
saveRecipeFromPost: async (post: FeedPost, myKitchenId: string, myHouseholdId: string) => {
  try {
    const userId = (await supabase.auth.getUser()).data.user?.id;
    if (!userId) {
      console.warn('[socialStore] saveRecipeFromPost: no authenticated user');
      return null;
    }

    if (!post.recipe_id) {
      console.warn('[socialStore] saveRecipeFromPost: post has no recipe_id');
      return null;
    }

    // Use SECURITY DEFINER RPC to clone recipe across household boundary (SAVE-01)
    const { data: newRecipeId, error: rpcError } = await supabase
      .rpc('clone_recipe_to_household', {
        p_source_recipe_id: post.recipe_id,
        p_target_household_id: myHouseholdId,
        p_source_kitchen_id: post.kitchen_id,
        p_created_by: userId,
      });

    if (rpcError) throw rpcError;
    if (!newRecipeId) {
      console.warn('[socialStore] saveRecipeFromPost: clone returned null');
      return null;
    }

    // Record in saved_recipes junction table
    await supabase
      .from('saved_recipes')
      .insert({
        kitchen_id: myKitchenId,
        source_kitchen_id: post.kitchen_id,
        recipe_id: newRecipeId,
        feed_post_id: post.id,
      });

    // Fetch the cloned recipe to return it
    const { data: newRecipe } = await supabase
      .from('recipes')
      .select('*')
      .eq('id', newRecipeId)
      .single();

    return (newRecipe as Recipe) ?? null;
  } catch (error: unknown) {
    console.warn('[socialStore] saveRecipeFromPost error:', getErrorMessage(error));
    return null;
  }
},
```

Key differences from the old implementation:
- No direct SELECT from recipes (which fails RLS cross-household)
- Single RPC call handles the clone atomically
- saved_from_kitchen_id and saved_from_recipe_id are set by the RPC function (not tags)
- Remove the old `savedTag` logic that added "Saved from X" to the tags array
- The RPC function handles the INSERT with proper attribution fields

Also check if FeedList.tsx has any save-related logic that references the old approach. If FeedList calls `saveRecipeFromPost`, it should continue to work unchanged since the method signature `(post: FeedPost, myKitchenId: string, myHouseholdId: string)` is preserved.
