## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, reply indicator gap |
| sm | 8px | Compact element spacing, comment row vertical padding |
| md | 16px | Default element spacing, section padding, input padding |
| lg | 24px | Section padding, reply indent offset |
| xl | 32px | Layout gaps, empty state padding |
| xxl | 48px | Major section breaks |

Source: `src/theme/spacing.ts` (existing, no changes needed)

Exceptions: Comment avatars use 32px diameter (top-level) and 24px diameter (replies). Reply indent uses `spacing.lg + 32 + spacing.sm` = 64px left margin (avatar width + gap + indent). Touch targets on delete action use minimum 44px hit area via hitSlop.

### Input Bar (CommentInput)

- Sticky at bottom of comments section (within ScrollView, not fixed-position)
- `flexDirection: 'row'`, `alignItems: 'center'`, `paddingHorizontal: spacing.md`, `paddingVertical: spacing.sm`
- `borderTopWidth: StyleSheet.hairlineWidth`, `borderTopColor: colors.outlineVariant`
- `gap: spacing.sm`

- Input text: `bodyMd`, `color: colors.onSurface`
- Placeholder: "Add a comment...", `color: colors.onSurfaceVariant`
- `maxLength: 500`
- Send button: MaterialCommunityIcons `send`, size 22
- Send active: `color: colors.primary` (when input has trimmed text and not submitting)
- Send disabled: `color: colors.outlineVariant` (when input empty or submitting)

- Visible when user taps "Reply" on a comment

- Left text: "Replying to @{handle}" in `bodySm`, `color: colors.onSurfaceVariant`
- Right button: MaterialCommunityIcons `close`, size 16, `color: colors.outlineVariant`, cancels reply mode
- Tapping close reverts input to top-level comment mode

## Interaction Contracts

### Adding a Comment

1. User types in the input field at bottom of comments section
2. Send button activates when input has non-whitespace text
3. User taps send icon
4. On submit: input clears immediately, comment appears at bottom of list (optimistic insert with local timestamp)
5. On success: comment persists, no additional visual change
6. On failure: error toast shown ("Comment couldn't be posted..."), comment removed from list

### Replying to a Comment

1. User taps "Reply" on a top-level comment
2. Reply context banner appears above input: "Replying to @{handle}"
3. Input field auto-focuses and keyboard opens
4. User types reply and taps send
5. Reply appears nested under the parent comment with indent and smaller avatar
6. User can cancel reply by tapping X on context banner (reverts to top-level mode)

### Deleting a Comment

1. User long-presses on their own comment (or recipe creator long-presses any comment)
2. Haptic feedback: medium impact
3. Native Alert appears:
   - Title: "Delete comment"
   - Message: "Are you sure you want to delete this comment?"
   - Buttons: "Cancel" (default style) / "Delete" (destructive style, red text)
4. On confirm: comment removed from list immediately (optimistic), replies to that comment also removed
5. On failure: comment re-appears, error toast shown

### Pull-to-Refresh

- User pulls down on the comments list area
- Comments re-fetched from server
- ActivityIndicator shown during refresh
- No real-time updates (per CONTEXT.md decision)

### Refresh on Post

- After successfully posting a comment, the full comments list is re-fetched to ensure consistency
- This happens after the optimistic update, replacing the optimistic entry with the server-confirmed entry

## State Mapping

| State | Visual Treatment |
|-------|-----------------|
| Recipe loading | No comments section shown (existing skeleton handles this) |
| Comments loading | Section heading visible, ActivityIndicator centered below heading, input bar visible |
| Comments loaded, 0 comments | Section heading "Comments" (no badge), empty state text centered, input bar visible |
| Comments loaded, 1+ comments | Section heading with count badge, comment list rendered, input bar visible |
| Comment submitting | Input cleared, send button disabled, optimistic comment in list |
| Comment submit error | Error toast, optimistic comment removed |
| Reply mode active | Reply context banner visible above input, input focused |
| Reply mode inactive | No context banner, input posts as top-level comment |
| Delete confirmation | Native Alert dialog overlay |
| Deleting in progress | Comment fades out (opacity 0.5) during delete request |
| Fetch error | Error text shown in place of comment list, input bar still visible |

## Visual Distinction from Notes (CMNT-05)

Comments and Household Tips (notes) must be visually distinct. The following differentiators are specified:

| Property | Comments (new) | Household Tips (existing) |
|----------|---------------|--------------------------|
| Section icon | `comment-text-outline` | `account` (person icon) |
| Section label | "Comments" | "Household Tips" |
| Placement | Below CookPhotoGallery, above Method | Below Method section |
| Avatar style | Round photo avatar or initial circle | Round icon-only circle (no photo) |
| Author display | "@handle" with timestamp | Date only (no handle) |
| Background | No card background (flat list) | `surfaceContainer` card per note |
| Input style | Rounded pill input with send icon | Underline-only input with submit-on-enter |
| Scope | Public (household + followers) | Private per-household |
| Threading | One-level replies supported | No replies |
