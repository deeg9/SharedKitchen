  <files>src/stores/socialStore.ts</files>
  <action>
Add new state fields and actions to socialStore:

New state fields:
- `followers: KitchenProfile[]` — list of kitchens that follow the viewed profile
- `following: KitchenProfile[]` — list of kitchens the viewed profile follows
- `followListLoading: boolean` — loading state for follower/following lists

New actions:

1. `fetchFollowers(kitchenId: string)`:
   - Query follows table joining to kitchen_profiles to get follower profiles:
     ```
     supabase.from('follows')
       .select('follower_kitchen_id, kitchen_profiles!follows_follower_kitchen_id_fkey(id, display_name, bio, avatar_url, follower_count, following_count, household_id)')
       .eq('following_kitchen_id', kitchenId)
     ```
   - If the foreign key alias doesn't work with Supabase's auto-detection, use a two-step approach:
     a. Query follows to get follower_kitchen_ids
     b. Query kitchen_profiles with `.in('id', followerIds)`
   - Set `followers` with the results, set `followListLoading: false`

2. `fetchFollowing(kitchenId: string)`:
   - Same pattern but reversed:
     ```
     supabase.from('follows')
       .select('following_kitchen_id, kitchen_profiles!follows_following_kitchen_id_fkey(id, display_name, bio, avatar_url, follower_count, following_count, household_id)')
       .eq('follower_kitchen_id', kitchenId)
     ```
   - Fallback: two-step query if join doesn't resolve
   - Set `following` with the results, set `followListLoading: false`

3. `clearFollowLists()`:
   - Resets `followers: []`, `following: []`, `followListLoading: false`

NOTE: For the join queries, Supabase PostgREST may not auto-detect the FK relationship due to two FKs from follows to kitchen_profiles. If the `!fkey_name` hint doesn't work, use the two-step approach (fetch IDs, then fetch profiles). The two-step approach is reliable and the list is bounded (typical user has <100 followers).
