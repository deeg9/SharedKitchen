  <action>
    1. Create `supabase/migrations/00001_create_profiles.sql`:
       - `CREATE TABLE profiles` with columns: `id UUID REFERENCES auth.users(id) PRIMARY KEY`, `display_name TEXT`, `avatar_url TEXT`, `created_at TIMESTAMPTZ DEFAULT now()`.
       - Enable RLS on profiles.
       - Create policies: users can read own profile and co-member profiles (via household_members junction), users can update own profile.
       - Create trigger function `handle_new_user()` that inserts a profile row on `auth.users` INSERT. Use `COALESCE(NEW.raw_user_meta_data->>'full_name', NEW.email)` for display_name.
       - Create trigger `on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION handle_new_user()`.

    2. Create `src/stores/authStore.ts` -- Zustand store with:
       - State: `session: Session | null`, `user: User | null`, `initialized: boolean`, `loading: boolean`
       - Actions: `setSession(session)`, `setInitialized(initialized)`, `signOut()` (calls `supabase.auth.signOut()` and clears state)
       - Export `useAuthStore` hook

    3. Create `app/_layout.tsx` -- Root layout:
       - Load fonts using `useFonts` from `@expo-google-fonts/plus-jakarta-sans` (Bold, ExtraBold) and `@expo-google-fonts/inter` (Regular, Medium, SemiBold, Bold)
       - Keep splash screen visible via `expo-splash-screen` until fonts loaded AND auth initialized
       - Set up `supabase.auth.onAuthStateChange` listener that updates authStore
       - Use `useSegments` and `useRouter` to redirect: session exists + in auth group -> redirect to `/(app)/(tabs)/plan`; no session + not in auth group -> redirect to `/(auth)/sign-in`
       - Render `<Slot />` (or `<Stack />` with no header)

    4. Create `app/(auth)/_layout.tsx` -- Simple Stack layout for auth screens, no header.

    5. Create `app/(auth)/sign-in.tsx`:
       - Email input, password input, "Sign In" button
       - Calls `supabase.auth.signInWithPassword({ email, password })`
       - "Sign in with Google" button that calls the Google OAuth flow:
         - Generate raw nonce with `expo-crypto`, hash with SHA-256
         - Call `GoogleSignin.signIn({ nonce: hashedNonce })`
         - Pass idToken and raw nonce to `supabase.auth.signInWithIdToken({ provider: 'google', token, nonce: rawNonce })`
       - Link to sign-up screen
       - Show error messages via Alert or inline text
       - Basic styling (will be refined in Plan 03 design system)

    6. Create `app/(auth)/sign-up.tsx`:
       - Email input, password input, confirm password input, "Create Account" button
       - Calls `supabase.auth.signUp({ email, password })`
       - Validate passwords match before submitting
       - Link back to sign-in screen

    7. Create `app/(app)/_layout.tsx` -- Authenticated layout. Simple Stack with `<Slot />`. The root layout handles redirect if no session, so this just renders children.

    8. Create `app/(app)/(tabs)/_layout.tsx` -- Basic Tabs layout with 5 tabs: Plan, Recipes, Grocery, Budget, Profile. Use expo-router `<Tabs>` component. Use basic icons for now (will be replaced with custom TabBar in Plan 03). Tab names: "Plan", "Recipes", "Grocery", "Budget", "Profile".

    9. Create placeholder tab screens: `plan.tsx`, `recipes.tsx`, `grocery.tsx`, `budget.tsx` -- Each renders a centered `<Text>` with the tab name + "Coming soon". `profile.tsx` renders "Profile" placeholder (will be built out in Plan 03).

    10. Update `tests/auth.test.ts` -- Fill in the skeleton tests:
        - "signup": Mock `supabase.auth.signUp`, verify it's called with email and password
        - "google": Mock `GoogleSignin.signIn` and `supabase.auth.signInWithIdToken`, verify nonce is passed
        - "signout": Mock `supabase.auth.signOut`, verify it clears the session

    IMPORTANT: Do NOT use hardcoded colors. Use simple default React Native styling for now. Plan 03 will apply the full design system. The goal here is working auth, not pretty UI.

    IMPORTANT: For Google OAuth, wrap the GoogleSignin calls in a try-catch. If GoogleSignin is not configured (no client IDs), show a user-friendly message rather than crashing.
