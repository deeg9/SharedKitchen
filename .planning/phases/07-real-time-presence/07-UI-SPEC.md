## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, avatar stack gap between toast avatar and text |
| md | 16px | Default element spacing, toast internal padding, toast horizontal margins |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| xxl | 48px | Major section breaks |

Exceptions: Avatar stack overlap uses -8px negative margin (not a spacing token, layout-specific offset for overlapping circles).

## PresenceAvatarStack Visual Spec

**Layout:** Horizontal row, avatars overlapping left-to-right.

| Property | Value |
|----------|-------|
| Avatar size | sm (32px diameter) |
| Avatar ring | 2px solid, color: surface (#fbf9f5) |
| Overlap offset | -8px marginLeft per avatar after the first |
| Z-index stacking | First avatar highest z-index (leftmost on top) |
| Max visible | 3 avatars before overflow badge |
| Overflow badge | 32px diameter circle, bg: primaryContainer (#4a5d4e), text: onPrimaryContainer (#c0d5c2), fontSize 11px, fontWeight 700 |
| Empty state | Component returns null (renders nothing when members.length === 0) |

**Placement:**

| Screen | Position | Alignment |
|--------|----------|-----------|
| Grocery list (grocery.tsx) | Left side of titleRow, before screen title | verticalCenter with title text |
| Recipe detail (recipe/[id].tsx) | Hero overlay area, right side, aligned with action buttons | position: absolute, right: 60px, top: insets.top + spacing.xs + 6 |

## ActivityToast Visual Spec

**Layout:** Horizontal row with avatar + text column, floating above screen content.

| Property | Value |
|----------|-------|
| Position | absolute, top: 60px (below status bar + nav), left: spacing.md (16px), right: spacing.md (16px) |
| Background | surfaceContainerLowest (#ffffff) |
| Border | 1px solid outlineVariant (#c3c8c1) — ghost border per design system |
| Border radius | borderRadius.lg (16px) |
| Shadow | shadows.float (0 4px 24px rgba(27,28,26,0.06)) |
| Internal padding | spacing.md (16px) all sides |
| Gap | spacing.sm (8px) between avatar and text column |
| Z-index | 1000 (above all screen content) |

**Text layout:**

| Element | Token | Color |
|---------|-------|-------|
| Display name | labelLg (14px, 600 weight) | primary (#334537) |
| Action message | bodySm (12px, 400 weight) | onSurfaceVariant (#434843) |

**Animation:**

| Phase | Property | Duration | Easing |
|-------|----------|----------|--------|
| Enter | translateY: -100 to 0 | 300ms | withTiming default (ease-in-out) |
| Enter | opacity: 0 to 1 | 300ms | withTiming default |
| Visible | hold | 3000ms (configurable via duration prop) | n/a |
| Exit | translateY: 0 to -100 | 300ms | withTiming default |
| Exit | opacity: 1 to 0 | 300ms | withTiming default |
| Dismiss callback | onDismiss() fires via runOnJS after exit completes | — | — |

**Queuing:** Only one toast visible at a time. If multiple events arrive within the 3000ms display window, queue them and show sequentially. Do not stack multiple toasts.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Toast: grocery check-off | "{display_name}" + "checked off {item_name}" |
| Toast: grocery uncheck | "{display_name}" + "unchecked {item_name}" |
| Toast: meal plan add | "{display_name}" + "added {recipe_name} to {day_name}" |
| Toast: meal plan update | "{display_name}" + "updated {day_name}'s dinner" |
| Toast: meal plan remove | "{display_name}" + "cleared {day_name}'s dinner" |
| Empty state (no presence) | No visible UI — PresenceAvatarStack returns null when no other members are viewing |
| Error state (channel failure) | No visible error UI — presence is a non-blocking enhancement; silently degrade to no avatars shown. Log error to console for debugging. |

**Notes:**
- There is no primary CTA in this phase. All UI elements are passive indicators (avatar stacks) or transient notifications (toasts).
- There are no destructive actions in this phase. Presence tracking and activity toasts are read-only awareness features.
- Toast messages use the exact field values from the database payload. Item names and recipe names are displayed as-is (no truncation unless they exceed the toast width, in which case use numberOfLines={1} with ellipsis).

## Interaction Contracts

### Presence Channel Lifecycle

| Event | Action |
|-------|--------|
| Screen mount (focused) | Create Supabase Presence channel, call channel.track() with current user data |
| Screen unmount / blur | Call channel.untrack(), then supabase.removeChannel() |
| App goes to background (AppState) | Call channel.untrack() — removes avatar from other users' screens |
| App returns to foreground (AppState) | Call channel.track() — re-adds avatar |
| Sync event received | Debounce 300ms, then read presenceState(), filter out self, update React state |

### Activity Toast Lifecycle

| Event | Action |
|-------|--------|
| postgres_changes UPDATE on grocery_items (is_checked changed) | If checked_by !== currentUserId, enqueue toast |
| postgres_changes INSERT/UPDATE/DELETE on meal_plans | If created_by !== currentUserId, enqueue toast |
| Toast enters queue | If no toast visible, show immediately. If toast visible, wait for current to dismiss. |
| Toast auto-dismiss | After 3000ms, animate out, call onDismiss, dequeue, show next if queued |
| App goes to background | Clear toast queue, dismiss any visible toast |

### Self-Filtering Rules

| Channel | Filter Logic |
|---------|-------------|
| Presence sync | Exclude entries where key === currentUser.user_id |
| Grocery activity | Exclude events where payload.new.checked_by === currentUserId |
| Meal plan activity | Exclude events where payload.new.created_by === currentUserId |

### Push Notification Deconfliction

Activity toasts (RT-03) are in-app-only UI, visible only when the app is foregrounded. They do NOT replace or duplicate push notifications from Phase 6. Phase 6 push notifications handle background/closed-app alerts for low-frequency events (leftover expiry, budget warnings). Phase 7 toasts handle high-frequency collaborative events (grocery check-offs, meal plan changes) that are only meaningful when the user is actively using the app.
