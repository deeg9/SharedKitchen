**Functions:**

1. `scaleNutrition(perHundredG: NutritionData, servingWeightG: number): NutritionData` - Multiplies all nutrition fields by (servingWeightG / 100). Rounds to 1 decimal. For optional fields, only include if present in input. Apply sanity cap: if input calories > 900 per 100g, cap at 900 (no food exceeds pure fat at ~900 kcal/100g).

2. `sumNutrition(items: NutritionData[]): NutritionData` - Element-wise sum of all NutritionData in the array. Returns zeros for required fields if array is empty. For optional fields, sum only where present.

3. `volumeToGrams(unit: string, foodName: string): number | null` - Converts a volume measurement to grams using FOOD_DENSITIES. Normalizes foodName to lowercase and tries partial matching (e.g., "all-purpose flour" matches "2 cups all-purpose flour"). Returns null if food not found in density table or unit is not a volume unit.

4. `convertToGrams(amount: number, unit: string, foodName?: string): number | null` - Unified conversion to grams. If unit is a weight unit, use WEIGHT_TO_GRAMS directly. If unit is a volume unit and foodName is provided, use volumeToGrams. Returns null if conversion cannot be determined.

5. `extractNutritionSummary(data: NutritionData): NutritionSummaryData` - Extracts the big-6 fields (calories, protein_g, total_fat_g, total_carbs_g, dietary_fiber_g, sodium_mg). Defaults dietary_fiber_g to 0 if absent.

6. `isNutritionDataValid(data: NutritionData): boolean` - Sanity check: calories should be >= 0 and <= 900, protein + fat + carbs should be <= 100g per 100g, all required fields are finite numbers.

Also create `src/lib/__tests__/nutrition-utils.test.ts` with tests for all the behaviors listed above. Use the project's test runner (Jest via Expo).

The existing `src/lib/unit-conversion.ts` handles metric/imperial display conversion for recipes. This new module handles food-specific density conversion for nutrition computation. They are complementary, not overlapping.
