  <action>
Create `supabase/functions/food-search/index.ts` following the exact Edge Function pattern from `search-recipes/index.ts`. The function handles POST requests with `{ query: string }` body.

**Structure (in order):**

1. **CORS headers constant** — identical to search-recipes pattern.

2. **USDA nutrient number mapping** — map nutrient numbers to NutritionData fields:
   ```
   208 -> calories, 203 -> protein_g, 204 -> total_fat_g, 205 -> total_carbs_g,
   291 -> dietary_fiber_g, 269 -> total_sugars_g, 606 -> saturated_fat_g,
   605 -> trans_fat_g, 601 -> cholesterol_mg, 307 -> sodium_mg,
   324 -> vitamin_d_mcg, 301 -> calcium_mg, 303 -> iron_mg, 306 -> potassium_mg
   ```

3. **FatSecret OAuth token cache** — in-memory `let tokenCache: { token: string; expiresAt: number } | null = null`. Function `getFatSecretToken()` posts to `https://oauth.fatsecret.com/connect/token` with Basic auth header (`btoa(CLIENT_ID + ':' + CLIENT_SECRET)`), body `grant_type=client_credentials&scope=premier`. Cache token with 2-minute buffer before expiry.

4. **USDA normalizer** — `normalizeUSDAFood(food)` that:
   - Maps `foodNutrients` array using nutrient number mapping (NOT nutrient name)
   - Sets `source: 'usda'`
   - Sets `data_quality`: Foundation=90, SR Legacy=80, Branded=40
   - Sets `name_normalized` to `food.description.toLowerCase().trim()`
   - Sets `fdc_id` from `food.fdcId`
   - Sets `brand` from `food.brandOwner ?? null`
   - Sets `barcode` from `food.gtinUpc ?? null`

5. **FatSecret normalizer** — `normalizeFatSecretFood(food)` that:
   - Handles array/object quirk: `const servings = Array.isArray(food.servings?.serving) ? food.servings.serving : food.servings?.serving ? [food.servings.serving] : []`
   - Finds per-100g serving: `servings.find(s => s.serving_description === '100 g' || s.metric_serving_amount === '100.000')`
   - If no per-100g serving, scales from first serving using `100 / parseFloat(baseServing.metric_serving_amount || '100')`
   - All FatSecret numeric values are STRINGS — must `parseFloat()` every field
   - Sets `source: 'fatsecret'`, `fatsecret_id: parseInt(food.food_id)`
   - Sets `data_quality`: Generic=70, Brand=60
   - Maps serving nutrition fields: `calories`, `protein` -> protein_g, `fat` -> total_fat_g, `carbohydrate` -> total_carbs_g, `sodium` -> sodium_mg, `saturated_fat`, `fiber`, `sugar`, `cholesterol`, `potassium`

6. **Deduplication** — `deduplicateResults(usdaResults, fsResults)` that:
   - Starts with USDA results
   - For each FatSecret result, checks if any USDA result has matching `name_normalized` (exact match or substring containment)
   - Only adds FatSecret results that are NOT duplicates
   - Sorts final array by `data_quality` descending

7. **Main handler** (`Deno.serve`):
   a. CORS preflight
   b. Auth via `supabaseClient.auth.getUser()` — return 401 if no user
   c. Admin client with `SUPABASE_SERVICE_ROLE_KEY`
   d. Parse body, validate `query` (string, trimmed length >= 2, max 100 chars)
   e. **Premium check** — query `subscriptions` table with try/catch (identical to search-recipes)
   f. **Daily rate limit** — count `ai_usage_log` rows where `user_id` matches, `function_name = 'food-search'`, and `created_at >= dayStart` where `dayStart = new Date(); dayStart.setHours(0,0,0,0)`. Limit: 20/day free, unlimited premium. Return 429 with `{ error, limit: 20, used, type: 'search_limit_exceeded' }` if exceeded.
   g. **Normalize query** — `query.toLowerCase().trim().replace(/\s+/g, ' ')`
   h. **Generate cache key** — SHA-256 hash of normalized query using `crypto.subtle.digest('SHA-256', new TextEncoder().encode(normalizedQuery))`, convert to hex string
   i. **Check food_search_cache** — select from `food_search_cache` where `query_hash` matches AND `expires_at > now()`. If hit, return cached results directly (the `results` JSONB column contains `FoodSearchResult[]`).
   j. **Check API key presence** — if `USDA_API_KEY` is not set, return 500 with `{ error: 'Food search not configured' }`
   k. **Parallel external API search** with 15-second timeout each via AbortController:
      - USDA: `GET https://api.nal.usda.gov/fdc/v1/foods/search?api_key={key}&query={query}&dataType=Foundation,SR Legacy,Branded&pageSize=25&sortBy=dataType.keyword&sortOrder=asc`
      - FatSecret: `GET https://platform.fatsecret.com/rest/foods/search/v3?search_expression={query}&max_results=15&format=json&flag_default_serving=true` with `Authorization: Bearer {token}` header
      - Use `Promise.allSettled()` so one API failure doesn't block the other
      - Handle FatSecret array/object quirk for results: `Array.isArray(data.foods_search?.results?.food) ? ... : data.foods_search?.results?.food ? [data.foods_search.results.food] : []`
   l. **Normalize and deduplicate** — call normalizers then deduplicateResults
   m. **Upsert into food_items** — for each result, upsert using `supabaseAdmin.from('food_items').upsert(item, { onConflict: source === 'usda' ? 'fdc_id' : 'fatsecret_id' })`. Build the full food_items row with all fields (id excluded — let Postgres generate). Use individual upserts in a `Promise.all()` to handle mixed conflict columns.
   n. **Build FoodSearchResult array** — map each upserted item to `{ id, name, brand, source, calories: nutrition.calories, protein_g: nutrition.protein_g, total_fat_g: nutrition.total_fat_g, total_carbs_g: nutrition.total_carbs_g, image_url }`
   o. **Write to food_search_cache** — upsert `{ query_hash, query_text: normalizedQuery, results: searchResults, result_count: searchResults.length }` (let Postgres defaults handle `created_at` and `expires_at`)
   p. **Non-blocking usage logging** — `supabaseAdmin.from('ai_usage_log').insert({ user_id, function_name: 'food-search', input_hash: null, cached_response: null, tokens_used: 0 }).then(() => {}).catch(() => {})`
   q. **Return response** — `{ results: searchResults }` with 200 and corsHeaders

**Error handling:**
- Wrap entire handler in try/catch, return 500 on unexpected errors
- If USDA fails but FatSecret succeeds (or vice versa), return partial results
- If both external APIs fail AND no cache hit, return `{ results: [], error: 'No results found' }` with 200
- AbortError from timeout returns 504

## Trust Boundaries

| Boundary | Description |

| Client -> Edge Function | Untrusted search query from mobile app |
| Edge Function -> USDA API | Outbound with API key as query param |

| Edge Function -> Postgres | Service role writes to food_items, food_search_cache, ai_usage_log |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-01 | Information Disclosure | API keys | mitigate | USDA_API_KEY, FATSECRET_CLIENT_ID/SECRET stored as Supabase secrets, never exposed to client. Edge Function is server-side only. |
| T-36-02 | Denial of Service | Rate limit bypass | mitigate | Server-side daily rate limit via ai_usage_log count, enforced before any external API call. 20/day free, unlimited premium. |
| T-36-03 | Tampering | Search query injection | mitigate | Validate query: string type, trimmed length 2-100 chars, normalize before passing to external API URLs via URL search params (auto-encoded). |
| T-36-04 | Tampering | Cache poisoning | mitigate | Only service_role can write to food_items and food_search_cache (RLS enforced). Client has SELECT-only access. |
| T-36-05 | Spoofing | Unauthenticated access | mitigate | Auth check via supabase.auth.getUser() at handler start, return 401 if missing. |
</threat_model>
