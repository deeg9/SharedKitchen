### New UI States (No New Components)

Phase 5 adds no new screens or components. All UI changes are modifications to existing premium components with new states:

1. **Checkout loading state** -- SubscriptionSheet and UpgradePrompt "Upgrade to Premium" button shows `ActivityIndicator` (white, size 18) replacing button text, with "Preparing secure checkout..." below the button in `bodySm` / `onSurfaceVariant`. Button is disabled during loading.

2. **Checkout failure state** -- Rendered inline in SubscriptionSheet below the Upgrade button area. Uses `errorContainer` (#ffdad6) background, `borderRadius.md` (12px), `spacing.md` (16px) padding. Contains error icon (`MaterialCommunityIcons` "alert-circle", size 20, `error` color), heading in `bodyMd` at 14px Inter 500, body in `bodySm` at 12px Inter 500, and "Retry Payment" button (variant "secondary", size "md").

3. **Past-due warning banner** -- Shown at top of SubscriptionSheet when status is `past_due`. Full-width banner with `errorContainer` (#ffdad6) background, `spacing.md` padding, `borderRadius.md` corners. Warning icon + copy from Status States table. "Update Payment" button opens billing portal.

4. **Canceled notice** -- Shown at top of SubscriptionSheet when status is `canceled`. Uses `surfaceContainerHigh` (#eae8e4) background. Includes expiry date and "Resubscribe" button that triggers checkout flow.

5. **Billing portal loading** -- "Manage Subscription" button shows `ActivityIndicator` inline replacing text. Brief state (Stripe portal URL returned in <1s typically).

6. **Rate limit warning** -- When `remaining <= 3` imports, show a subtle `bodySm` line below the import URL input: "{remaining} imports left today" in `onSurfaceVariant`. When limit exceeded, replace import button area with error card using same pattern as checkout failure state, with rate limit copy from Copywriting Contract.

## Interaction Contracts

### Checkout Flow Sequence

1. User taps "Upgrade to Premium" button
2. Button enters loading state (disabled, ActivityIndicator, "Preparing secure checkout..." below)
3. App calls `create-checkout-session` Edge Function via Supabase
4. Stripe `initPaymentSheet()` + `presentPaymentSheet()` opens native PaymentSheet overlay
5. **On success:** PaymentSheet dismisses. App polls `subscriptions` table every 2s for up to 10s. When `active` status found, SubscriptionSheet re-renders to Premium Plan view with PRO badge. If poll times out, show success-with-delay message: "Payment received! Your premium status will update shortly."
6. **On cancel:** PaymentSheet dismisses. Button returns to normal state. No error shown.
7. **On failure:** PaymentSheet dismisses. Checkout failure state renders inline per Component Inventory above.

### Billing Portal Flow Sequence

1. User (premium) taps "Manage Subscription"
2. Button enters loading state (ActivityIndicator replacing text)
3. App calls `create-billing-portal` Edge Function
4. App opens returned URL in system browser (`Linking.openURL()`)
5. Button returns to normal state after 1s delay (portal opens externally)
6. On app foreground resume, `subscriptionStore.refreshSubscription()` re-queries subscription state

### Recipe Import Flow (Updated)

1. User pastes URL and taps "Import Recipe" (existing flow)
2. Button enters loading state (existing pattern)
3. Edge Function checks rate limit before calling OpenAI
4. **On 429 response:** Show rate limit error card with appropriate copy (free vs premium)
5. **On success:** Parsed recipe populates form (existing behavior, now using gpt-5-mini)
6. **On error:** Show existing error message (no visual change)
