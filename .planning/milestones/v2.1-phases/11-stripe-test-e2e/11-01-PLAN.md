**Bug fix (PAY-03):** The create-checkout-session Edge Function has TWO bugs:

Bug A: The existing upsert (lines 60-66) only runs inside the `if (!customerId)` block, so returning users who already have a stripe_customer_id skip it entirely and never get a row update.

Bug B: Even for new users, the existing upsert runs BEFORE `stripe.subscriptions.create()` so it cannot include the subscription ID.

Both bugs mean the webhook handler's `customer.subscription.updated` case (which matches by `.eq('stripe_subscription_id', subscriptionId)`) will never find the row.

**Fix — do NOT touch the existing `if (!customerId)` block (lines 52-67). Leave it as-is.** Instead, add a NEW unconditional upsert AFTER `stripe.subscriptions.create()` (after line 95) and BEFORE the return statement (line 100). This upsert runs for ALL users (new and returning):

```typescript
// Store subscription ID so webhooks can match this row (runs for ALL users)
await supabaseAdmin
  .from('subscriptions')
  .upsert({
    user_id: user.id,
    stripe_customer_id: customerId,
    stripe_subscription_id: subscription.id,
    status: 'free',
  }, { onConflict: 'user_id' })
```

Insert this between line 95 (`})` closing subscriptions.create) and line 97 (`const invoice = ...`). The existing upsert inside `if (!customerId)` at lines 60-66 can remain — it seeds the row for new users, and the new unconditional upsert will update it with the subscription ID moments later.

The complete flow after the fix:
1. Check for existing stripe_customer_id (lines 43-47) — unchanged
2. Create Stripe customer if needed (lines 52-67) — unchanged, seeds row for new users
3. Create subscription (lines 86-95) — unchanged
4. **NEW: Unconditional upsert with user_id + stripe_customer_id + stripe_subscription_id** — works for both new AND returning users
5. Return response — unchanged

**Setup guide (PAY-02):** Create STRIPE_SETUP.md at project root with:

# Stripe Test Mode Setup

## Prerequisites
- Stripe account (https://dashboard.stripe.com/register)
- Supabase CLI installed (`supabase --version`)
- Stripe CLI installed (`stripe --version`)

## 1. Get Test API Keys
- Go to Stripe Dashboard > Developers > API Keys
- Copy Publishable key (`pk_test_...`) and Secret key (`sk_test_...`)

## 2. Create a Product and Price
- Go to Stripe Dashboard > Products > Add Product
- Name: "Mise Premium", Price: $9.99/month recurring
- Copy the Price ID (`price_...`)

## 3. Configure Client Environment
Add to your `.env` file:
```
EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_your-key
EXPO_PUBLIC_STRIPE_PRICE_ID=price_your-price-id
```

## 4. Set Supabase Edge Function Secrets
```bash
supabase secrets set STRIPE_SECRET_KEY=sk_test_your-key
supabase secrets set STRIPE_PRICE_ID=price_your-price-id
supabase secrets set STRIPE_WEBHOOK_SIGNING_SECRET=whsec_your-signing-secret
```

Note: SUPABASE_URL, SUPABASE_ANON_KEY, and SUPABASE_SERVICE_ROLE_KEY are auto-injected by Supabase.

## 5. Deploy Edge Functions
```bash
supabase functions deploy create-checkout-session
supabase functions deploy stripe-webhooks
supabase functions deploy create-billing-portal
```

## 6. Configure Webhook Endpoint
- Go to Stripe Dashboard > Developers > Webhooks > Add endpoint
- URL: `https://<project-ref>.supabase.co/functions/v1/stripe-webhooks`
- Events: checkout.session.completed, customer.subscription.updated, customer.subscription.deleted, invoice.payment_failed
- Copy the Signing secret (`whsec_...`) and update the secret from step 4

## 7. Configure Customer Portal
- Go to Stripe Dashboard > Settings > Billing > Customer portal
- Enable portal and save

## 8. Local Testing with Stripe CLI
```bash
# Forward webhooks to local Supabase
stripe listen --forward-to http://localhost:54321/functions/v1/stripe-webhooks

# Use the provided webhook signing secret for local testing
```
