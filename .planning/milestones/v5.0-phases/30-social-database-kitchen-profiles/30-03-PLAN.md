## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Search input to database query | User-typed search query used in ilike pattern |
| Invite code exposure | Invite code shared externally via system share sheet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-10 | Tampering | Search query injection | mitigate | Supabase client parameterizes queries. ilike pattern is `%${query}%` passed through Supabase JS SDK which handles escaping. No raw SQL. |
| T-30-11 | Information Disclosure | Search results | mitigate | Search only returns profiles with is_searchable=true. Only select id, display_name, bio, avatar_url, follower_count -- no household_id or invite_code in search results. |
| T-30-12 | Denial of Service | Excessive search queries | accept | Debounce at 300ms client-side. At current scale (<10K kitchens), acceptable. Rate limiting can be added at API level later if needed. |
| T-30-13 | Information Disclosure | Invite code in share | accept | Invite codes are intentionally shared. They only enable following (not joining household). 8-char codes provide sufficient entropy against brute-force. |
</threat_model>
