2. Create `reported_content` table:
```sql
CREATE TABLE reported_content (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  reporter_kitchen_id UUID NOT NULL REFERENCES kitchen_profiles(id) ON DELETE CASCADE,
  content_type TEXT NOT NULL CHECK (content_type IN ('post', 'comment')),
  post_id UUID REFERENCES feed_posts(id) ON DELETE CASCADE,
  comment_id UUID REFERENCES post_comments(id) ON DELETE CASCADE,
  reason TEXT CHECK (char_length(reason) <= 500),
  created_at TIMESTAMPTZ DEFAULT now(),
  CHECK (
    (content_type = 'post' AND post_id IS NOT NULL) OR
    (content_type = 'comment' AND comment_id IS NOT NULL)
  )
);
```

Add RLS:
```sql
ALTER TABLE reported_content ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Kitchen members can view own reports"
  ON reported_content FOR SELECT
  USING (is_kitchen_member(reporter_kitchen_id, (select auth.uid())));

CREATE POLICY "Kitchen members can report content"
  ON reported_content FOR INSERT
  WITH CHECK (is_kitchen_member(reporter_kitchen_id, (select auth.uid())));
```

**B. Add interaction methods to socialStore:**

1. `checkLikedPosts(myKitchenId: string, postIds: string[])` - Query post_likes where kitchen_id = myKitchenId and post_id in postIds. Set likedPostIds to result. Call this after fetchFeedPosts completes (in the same method or as a follow-up).

2. `toggleLike(postId: string, myKitchenId: string)` - Optimistic UI pattern (matching follow/unfollow):
   - If postId is in likedPostIds: remove from likedPostIds array, decrement post's like_count in feedPosts, then DELETE from post_likes. On error: rollback.
   - If postId is NOT in likedPostIds: add to likedPostIds array, increment post's like_count in feedPosts, then INSERT into post_likes. On error: rollback.
   - Update feedPosts in place using map to find and update the matching post.

3. `fetchComments(postId: string)` - Query post_comments where post_id = postId, ordered by created_at ASC. Store in `comments` state.

4. `addComment(postId: string, myKitchenId: string, content: string)` - Insert into post_comments. On success, append to `comments` array and increment matching feedPost's comment_count optimistically. The trigger handles the DB count.

5. `deleteComment(commentId: string, postId: string)` - Delete from post_comments. Remove from `comments` array and decrement matching feedPost's comment_count.

6. `saveRecipeFromPost(post: FeedPost, myKitchenId: string, myHouseholdId: string)` - Two-step:
   a. Look up the recipe by post.recipe_id. If null, look up via meal_plan_id: query meal_plans for recipe_id, then query recipes for full recipe data.
   b. Clone the recipe: call supabase.from('recipes').insert({...recipe fields, household_id: myHouseholdId, name: recipe.name, tags: [...(recipe.tags || []), 'Saved from ' + (kitchenProfile display_name or 'another kitchen')]}) — copy all fields except id, household_id, created_by, created_at, updated_at.
   c. Record in saved_recipes table: insert {kitchen_id: myKitchenId, source_kitchen_id: post.kitchen_id, recipe_id: newRecipe.id, feed_post_id: post.id}.
   d. Return the new recipe or null.

7. `reportContent(reporterKitchenId: string, contentType: 'post' | 'comment', postId?: string, commentId?: string, reason?: string)` - Insert into reported_content table. Fire-and-forget style, just log a warning on error.

8. `blockKitchen(myKitchenId: string, blockedKitchenId: string)` - Insert into blocked_kitchens. Add blockedKitchenId to blockedKitchenIds array. Then call refreshFeed to re-filter.

9. `unblockKitchen(myKitchenId: string, blockedKitchenId: string)` - Delete from blocked_kitchens. Remove from blockedKitchenIds array.

10. `fetchBlockedKitchens(myKitchenId: string)` - Query blocked_kitchens where blocker_kitchen_id = myKitchenId. Store blocked_kitchen_id values in blockedKitchenIds array.
