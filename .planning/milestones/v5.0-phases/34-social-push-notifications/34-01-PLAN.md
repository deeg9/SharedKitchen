<task type="auto">
  <name>Task 1: Create send-social-notification Edge Function</name>
  <files>supabase/functions/send-social-notification/index.ts</files>
  <action>
Create a new Supabase Edge Function at `supabase/functions/send-social-notification/index.ts` following the existing Edge Function pattern from `analyze-food-photo/index.ts` (Deno runtime, CORS headers, service_role admin client).

The function is called by database webhook triggers (configured in Plan 02) with a POST body containing:
```json
{
  "type": "INSERT",
  "table": "follows" | "post_likes" | "post_comments",
  "record": { ...row data... },
  "old_record": null
}
```

Implementation steps:

1. **CORS preflight** — handle OPTIONS, return `ok` with CORS headers.

2. **Validate webhook payload** — parse JSON body, extract `table` and `record`. Return 400 if missing.

3. **Create admin Supabase client** using `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (no user auth needed — this is a server-to-server webhook call). Add a shared webhook secret check: read `X-Webhook-Secret` header and compare to `Deno.env.get('SOCIAL_WEBHOOK_SECRET')`. Return 401 if mismatch.

4. **Determine notification details** based on `table`:
   - `follows`: actor = `record.follower_kitchen_id`, target kitchen = `record.following_kitchen_id`, message = "started following you"
   - `post_likes`: actor = `record.kitchen_id`, look up feed_post by `record.post_id` to get target kitchen = `feed_post.kitchen_id`, message = "liked your meal"
   - `post_comments`: actor = `record.kitchen_id`, look up feed_post by `record.post_id` to get target kitchen = `feed_post.kitchen_id`, message = "commented on your meal"

5. **Resolve actor kitchen name** — query `kitchen_profiles` for actor kitchen_id, get `display_name`.

6. **Self-notification prevention** — if actor kitchen_id === target kitchen_id, return 200 with `{ skipped: "self-action" }`.

7. **Resolve target users** — query `kitchen_profiles` JOIN `household_members` for target kitchen_id to get all user_ids in that household.

8. **Resolve actor users** — query `household_members` via kitchen_profiles for actor kitchen_id to get actor user_ids. These are used for self-notification prevention at user level (same household acting on own posts).

9. **Fetch push tokens** — query `push_tokens` table for all target user_ids (excluding actor user_ids), get their `expo_push_token` values.

10. **Check notification preferences** — This Edge Function does NOT check client-side AsyncStorage preferences (it cannot access device storage). The social toggle will be checked client-side before the action that triggers the webhook. For server-side, send to all tokens. (Note: if a `notification_preferences` table is added later, check it here.)

11. **Send via Expo Push API** — POST to `https://exp.host/--/api/v2/push/send` with:
    ```json
    [
      {
        "to": "ExponentPushToken[xxx]",
        "title": "SharedKitchen",
        "body": "{actorKitchenName} {message}",
        "data": { "type": "social", "table": "{table}", "postId": "{post_id or null}" },
        "sound": "default"
      }
    ]
    ```
    Send as a batch array if multiple tokens. Handle Expo API errors gracefully (log, don't throw).

12. **Return 200** with `{ sent: N }` where N = number of tokens notified.

Do NOT authenticate the calling user (this is webhook-to-function, not client-to-function). Use the webhook secret for auth instead.
