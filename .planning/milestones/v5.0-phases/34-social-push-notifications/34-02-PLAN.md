Create migration `supabase/migrations/00021_social_notification_webhooks.sql` that sets up Postgres triggers to call the `send-social-notification` Edge Function on social table inserts.

Use Supabase's `supabase_functions.http_request` (the built-in webhook trigger function available in all Supabase projects) rather than raw `pg_net`. This is the recommended approach for database webhooks in Supabase.

**If `supabase_functions.http_request` is not available**, fall back to using `net.http_post` from the `pg_net` extension (add `CREATE EXTENSION IF NOT EXISTS pg_net;`).

Create a single reusable trigger function and three triggers:

```sql
-- Trigger function that sends webhook to Edge Function
CREATE OR REPLACE FUNCTION notify_social_event()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  payload jsonb;
  edge_function_url text;
  webhook_secret text;
BEGIN
  -- Build payload matching Edge Function expected format
  payload := jsonb_build_object(
    'type', 'INSERT',
    'table', TG_TABLE_NAME,
    'record', row_to_json(NEW)::jsonb,
    'old_record', null
  );

  edge_function_url := current_setting('app.settings.supabase_url', true)
    || '/functions/v1/send-social-notification';
  webhook_secret := current_setting('app.settings.social_webhook_secret', true);

  -- Use pg_net to make async HTTP POST
  PERFORM net.http_post(
    url := edge_function_url,
    body := payload::text,
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'X-Webhook-Secret', webhook_secret
    )
  );

  RETURN NEW;
END;
$$;
```

NOTE: The executor should check which webhook mechanism is available in the Supabase project. The preferred approach order is:
1. `supabase_functions.http_request` — Supabase's built-in webhook function (check: `SELECT * FROM pg_proc WHERE proname = 'http_request' AND pronamespace = (SELECT oid FROM pg_namespace WHERE nspname = 'supabase_functions');`)
2. `net.http_post` from pg_net extension (check: `SELECT * FROM pg_extension WHERE extname = 'pg_net';`)
3. If neither available, create the triggers using `pg_net` with `CREATE EXTENSION IF NOT EXISTS pg_net;`

For the URL and secret, use Supabase Vault secrets or `current_setting()` with app-level config. The executor should use the approach that works best with the project's Supabase setup. The key requirement is: async HTTP POST to the Edge Function URL with the webhook secret header.

Create 3 triggers (all AFTER INSERT, FOR EACH ROW):

```sql
CREATE TRIGGER on_new_follow
  AFTER INSERT ON follows
  FOR EACH ROW
  EXECUTE FUNCTION notify_social_event();

CREATE TRIGGER on_new_like
  AFTER INSERT ON post_likes
  FOR EACH ROW
  EXECUTE FUNCTION notify_social_event();

CREATE TRIGGER on_new_comment
  AFTER INSERT ON post_comments
  FOR EACH ROW
  EXECUTE FUNCTION notify_social_event();
```
